# How Instances are licensed, signed in to, shipped and expired

Builds on ADR-0009.

- **Apps**: Instance Users use the official store apps, which hold an Instance address alongside Palmy Cloud and never mix their data. White-label apps per Licensee are a later paid add-on.
- **Sign-in**: an Instance signs Users in through the Licensee's own identity provider over OIDC (e.g. Entra ID, Keycloak, Okta, Google Workspace); Palmy never sees or stores credentials. Built-in email one-time codes may come later for Licensees without one.
- **What a Licence contains**: Licensee, Instance ID, the Instance's domain, expiry date, a cap on Active Users, Licensed features, and the ID of the key that signed it. The Licensee pays, so every User on an Instance gets all Licensed features: there are no Plans, Subscriptions, stores or Promo codes on Instances.
- **Binding**: a Licence is bound to an Instance ID and domain, not to hardware, because hardware fingerprints break whenever containers are rescheduled. The Instance refuses requests on any other domain; Check-ins reveal two Instances using one ID.
- **Signing**: the licence server is a separate service in the `api/` workspace, part of Backoffice. The private signing key lives in Google Cloud KMS and never leaves it. Instances embed several public keys so keys can be rotated. Sales Staff issue and renew Licences; only Admin revokes; every Licence action creates an Audit entry. Revocation only reaches Instances that Check in; offline Instances are bounded by their expiry date, so Licence terms should stay short (e.g. one year).
- **Shipping**: Instances are signed container images (cosign) in a private registry, pulled with a token tied to the Licence; the Instance verifies its own image signature at startup. Licensees choose when to upgrade; migrations run on start-up and are irreversible, so they must back up first. Palmy supports the latest two minor versions; an older version doesn't invalidate the Licence.
- **Expiry**: Staff and the Licensee's administrators are warned 30, 14 and 7 days before expiry. After expiry comes a 14-day Grace period (banner, writes still work), then the Instance becomes an Expired Instance (read-only).
