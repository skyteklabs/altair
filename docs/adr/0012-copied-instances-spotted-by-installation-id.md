# Copied Instances are spotted by an installation ID in Check-ins

Builds on ADR-0010. Every copy of an Instance shares its Licence and so its Instance ID, which alone can't tell one running copy from a restart. Each running copy therefore generates a random installation ID on first start, stores it with its data, and sends it in every Check-in; one Instance ID reporting two installation IDs at once is a Copied Instance. The installation ID is an implementation detail, not a domain term.

We accept two gaps: a copy goes unseen unless both it and the original Check in, and a copy made together with its data, such as a backup restored on a second server, carries the same installation ID and goes unseen too; that is likely the most common way to copy an Instance. A copy at another domain is only an Expired Instance (ADR-0011), so a copy worth running sits at the same domain, for example behind internal DNS. We rejected hardware fingerprints for the same reason as ADR-0010: they break whenever containers are rescheduled.
