# Licence problems degrade an Instance instead of stopping it

Builds on ADR-0009 and ADR-0010, and changes ADR-0010's domain refusal. When an Instance falls outside its Licence, it never refuses to start or hides data; it only stops new writes or new sign-ins, so a Licensee is never locked out of its records and its Users' day isn't interrupted. The one exception is tampering: a container image that fails its signature won't start (ADR-0009).

- **No valid Licence**: a Licence that is missing, malformed, signed by an unknown key, has a bad signature, names another Instance ID or another Instance address, or uses an unsupported format version makes the Instance an Expired Instance, the same as a revoked Licence or one past its Grace period. We rejected refusing to start, because a botched Licence file or a key-rotation mistake would then make a bank's records unreadable until Palmy responds. The check is against the Instance address the Licensee configures, not each request's hostname, so an Instance is either an Expired Instance or not. The address is self-declared: Palmy binds the Licence to the value the Licensee sets and does not verify the hostname actually served. A copy configured with another Instance address gains only read access to data it already holds, so refusing it outright buys nothing.
- **Active User cap**: at the Active User cap, Users who are already Active Users keep signing in; any other User is refused until an Active User lapses or a Licence with a higher Active User cap is installed. We rejected refusing everyone at the cap, because reaching a commercial limit should never cut off Active Users. Instance administrators are warned inside the Instance once Active Users reach 90% of the Active User cap; Staff learn of it only through Check-ins.
